# P8 素材识别与自动选段

入口：[客户商品制作](http://127.0.0.1:8765/create)。继续沿用 P7 的商品事实、文稿、配音听核和成片审核流程。

## 使用顺序

1. 新建商品项目，上传资料、商品图、实拍视频与配音。新页面项目默认勾选“根据文稿自动选段”。旧项目保持原设置。
2. 视觉素材会进入本机识别队列。可以继续整理产品事实和文稿。每份素材显示排队、抽帧、识别进度；支持取消和主动重试。
3. 展开“查看候选片段”，核对关键帧、实际时间范围、内容观察与不确定项。视频可点“播放这一段”。内容观察不是商品事实，也不是测评证据。
4. 识别完成、确认文稿后，准备制作版本并查看三个风格。非纯展示模式仍需上传成品配音、完成字级对齐与听核。
5. 选定风格，生成分镜：模型比较文稿与可见内容；程序只在已测量片段内选取足够时长。相同匹配程度时偏好视频，减少重叠片段；长镜头可分配不同的未用范围。
6. 每镜下方可查看初次自动安排理由；用“按识别内容换一段”挑选候选，再微调素材入点，预览并保存。自动建议不会持续覆盖已保存分镜。
7. 输出成片后只改不满意的镜头，生成新版本；其他镜头缓存继续复用，原成片和配音听核记录保留。最终影片仍需人工审片。

## 本机模型配置

模型是可选依赖；不需要 Secret 或平台账户。当前适配器只访问 `127.0.0.1:11434` 的 Ollama，不支持远程或 cloud 模型。第一次下载模型需要网络；制作时图片在本机处理。

推荐默认模型：[Qwen3-VL 2B / Ollama](https://ollama.com/library/qwen3-vl:2b)，官方库标注 Apache 2.0。模型体积约 1.9 GB，实际内存和速度取决于机器、上下文与素材数量。仅下载不代表识别质量已验收。

在终端启动 Ollama App，或运行 `ollama serve`（已有服务时无需重复）。在项目目录执行：

```sh
ollama pull qwen3-vl:2b
.venv/bin/python scripts/vision_setup.py
```

检查输出必须是 `ready: true` 并含本机模型摘要。脚本只读，不会安装或改变配置。默认无需设置环境变量；如选择另一个已安装视觉模型，启动服务前设置 `ECOM_VISION_MODEL` 为 `ollama list` 中的完整模型名。配置文件 `var/models/vision.json` 的 `model` 可作为默认值，环境变量优先。

**本机已通过真实图片识别检查。** Ollama 库与 Hugging Face 下载在这台机器上遇到非公网 DNS 重定向，因此采用 [Qwen 官方 ModelScope 仓库](https://modelscope.cn/models/Qwen/Qwen3-VL-2B-Instruct-GGUF) 的固定版本权重。两个文件合计约1.93 GB，SHA256 与 Qwen 官方 Hugging Face 文件元数据交叉核对。没有关闭 TLS 或公网地址校验，也没有修改全局网络。

本项目提供可恢复下载、校验和本机导入脚本：

```sh
.venv/bin/python scripts/download_qwen_vision.py
.venv/bin/python scripts/import_qwen_vision.py
```

安装名为 `ecom-qwen3vl:2b-q4km`，不会替换现有其他模型。下载完成不代表识别通过；本机演示另通过 `scripts/probe_p8_vision.py` 对示例杯盖图做真实结构化识别后，才写入 `var/models/vision.json` 启用模型。该探针依赖 `scripts/build_p8_live_demo.py` 和抽帧产生的演示图片，不是通用安装器。新机器安装后可以先用 `ECOM_VISION_MODEL=ecom-qwen3vl:2b-q4km .venv/bin/python scripts/vision_setup.py` 检查服务，再用自己的图片进行识别核对。

安装和本次真实运行证据见 P8 本机实测（历史记录或本机文件，未随公开版分发）。当前无需填写任何账户 Secret。

模型可用性与接口参考：[本机图像输入](https://docs.ollama.com/capabilities/vision)、[结构化输出](https://docs.ollama.com/capabilities/structured-outputs)。

## 模型未就绪仍可工作

系统先检测切点和抽帧，再尝试识别。缺模型、超时或结构错误时，状态为“已抽帧，内容识别未就绪”（`partial`），实际关键帧仍可查看。

关闭“根据文稿自动选段”，保存制作要求，再使用已确认文稿继续制作；候选时间范围可以人工挑选。这里没有自动语义识别。模型就绪后主动重试、重新准备制作版本，才会采用新的识别结果。单纯抽帧失败则显示 `failed`，不伪造候选内容。

## 当前能力边界

- 每段视频最多选取 8 个候选窗口，每窗口最多 2 帧；每张图片 1 帧。候选最长15秒。记录 `uncovered_ranges`，长视频不能保证覆盖每个动作，建议先按场景拆成短素材。
- FFmpeg 检测硬切，候选窗口在切点内留边。缓慢转场、遮挡、对焦变化、闪光和动作细节仍需人工检查；这是关键帧观察，不是连续动作理解或逐帧跟踪。
- 最多40个候选进入单次制作的文稿匹配上下文；逐句匹配文稿，返回句数与候选ID受结构约束，理由最多48字。无匹配且足长的画面会明确拒绝，需补充素材或切到手动模式。
- 0–3 匹配分是编辑评分，不是识别置信概率。只有相关且足长的候选才能自动采用；不会凭模型判断新增功效、身份或实验结论。
- 人工素材角色与来源说明保持不变。测评证据必须由人标注、填写来源，并满足原有测评要求。
- 单文件100 MiB等上传限制仍沿用原流程。没有新增云存储、自动上传、平台投放或客户素材外发。
- 一个素材分析 worker 顺序处理；单次模型请求最多240秒，整项任务最多30分钟。取消立即撤销结果发布权，正在进行的模型调用可能等待返回/超时才退出。崩溃后的过期租约会转为失败，须主动重试。
- 本机8 GB机器已完成真实单图探针。客户尚未提供实拍；虚构示例的图片动画不能证明真实拍摄素材的识别质量，仍需客户素材验收。

## 数据与版本

新增 `media_analyses` 表，schema 8。分析记录绑定源文件 SHA256、模型摘要、引擎签名和候选范围；准备任务时将结果冻结到素材元数据中。更换素材或分析版本会使旧准备版本失效，已输出的影片不会被自动改写。

当前 ready/partial 关键帧保留供预览；失败/取消的未引用关键帧在 worker 收尾清理，重试清理旧 partial。删除素材时清理无历史版本引用的衍生文件；历史成片素材及分析证据继续保留，和 P7 的历史版本策略一致。
