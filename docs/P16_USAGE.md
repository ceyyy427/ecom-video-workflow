# P16：创意假设、人工选择与下一轮复盘

本阶段只做本地、可审计的描述性迭代。用户选择假设和制作版本，客户负责投放、账户及报表。无新云调用、无自动投放、训练、预算调整、显著性检验或因果归因。

## 启用

```sh
ECOM_AGENT_ENABLED=1 ECOM_AGENT_EXECUTION_ENABLED=1 ECOM_REVIEW_SNAPSHOTS_ENABLED=1 ECOM_EXPERIMENTS_ENABLED=1 .venv/bin/python -m ecom_video
```
`.env.example` 不会自动加载；P16 默认关闭，开关仅控制新入口。已有迭代草稿的人工守卫即使关开关仍有效，不能用旧提交入口绕过。

## 从冻结复盘到下一版

1. 在 `/distribution` 导入完整素材日报，人工关联平台素材与已审核父成片，冻结基准。父片须来自同一个客户商品项目、是当前版本，且当前事实/文稿/素材/配音仍匹配；没有项目归属的旧任务可继续原制作/复盘，但不会补造实验归属。
2. 在冻结素材卡点击“基于此冻结素材提出创意假设”，或打开 `/experiments` 填基准 review_id/material_id。填写实际记录人，读取依据后写假设、观察指标与最少上报天数/曝光门槛。假设只是待验证建议，没有模型或统计证据背书。
3. 选择修改一个镜头（如实拍入点、运镜、构图、短字卡或同项目替换素材），或修改带已确认事实引用的文稿。可编辑的 JSON 是严格数据，不执行代码；产品陈述需引用已确认 fact_ids。新事实请回客户制作页核对，再重新建提案。
4. 保存后状态为 proposed，不改片。填写说明并勾选核对，再人工选择或拒绝。selected 后另点击“应用为新版草稿”；每个提案只产生一个领域结果，重试不会重复建片。
5. 改画面沿用原单镜修订、素材拷贝与事实/稿件来源，新版为 draft；父片不变。打开客户制作页核对分镜，逐句试听后点击“确认本版配音听核”（已有分镜也可独立保存听核）；然后回迭代页刷新并确认本版当前风格。改分镜后须再次确认。原流程最终提交渲染、人工审片放行。
6. 改稿只保存未批准的新稿件，不自动批准或建片。去客户制作页人工核对确认文稿、提供匹配配音、准备制作版本；回迭代页“关联该新稿件的草稿”。仅接受该新稿件、同产品的当前 draft，关联后 parent_id 指向父成片，新的脚本审批来源仍保留在 provenance。再选风格、对齐/听核、制作、审片。
7. 制作页顶部有本版父片/基准复盘提示和返回迭代的链接；风格未确认时生成按钮停用。所有提交 API 同样检查，不能靠旧入口跳过。普通非 P16 任务原行为不变。
8. 新版 ready 后，可点击等待客户数据；这不是平台提交回执，也不会调用平台。客户自行投放后，人工绑定新平台素材 ID→该新版，导入下一轮报表并冻结；不要复用父素材 ID。
9. 在迭代页选择下一轮复盘与素材，保存新的描述性评估；重导报表时先新冻结，再新增评估。旧评估、旧快照、父片与来源均不变。下载完整迭代 JSON 留档；最近列表50条，更早可完整ID打开。

## 口径、缺失与对比

- 仅比较同账户、同产品、确切绑定选定新版的素材。未关联或绑定其他版本的行不作为新版表现，下一轮值未知。不同账户直接拒绝。
- 两轮窗口须等长、不重叠，下一轮开始在基准结束之后；原始字段完整、符合用户选择的天数/曝光门槛，币种/时区/指标定义/算法/归因窗口一致，才计算描述性差值。
- CSV 导入可选填归因窗口并单独确认它与平台导出设置一致；照抄实际设置，不确定就留空，不能为让检查通过而填写示例。该字段是人工声明，未向平台验证。相同原文件更正声明会产生另一批次，旧声明/快照不改写；重复相同文件与声明仍去重。
- 缺数据、窗口未知或冲突、曝光不足等标 insufficient_evidence，保存原因和可采用的原值，不给可比差值或胜出结论；之后可以补数据再新冻结/评估。
- 先按 P15 原始指标合计再算比率；差值与相对变化用 Decimal、六位 HALF_EVEN。CTR/完播率是0–1比例，0.1→0.2 的差值为0.1（10个百分点），相对变化为1（100%），不是提升1个百分点。基准值0时相对变化未知，可保留绝对差。
- “可读取描述性差值”只表示这些数据满足所选可计算条件；没有控制日期、人群、计划、流量或商品环境差异，不代表该创意导致变化，winner始终为空。不在这里做计划/人群/商品维度的因果实验。

## API

继承本机 Host/Origin/session 保护。`/api/experiments/capabilities` 返回开关/严格 schema；其它 P16 路由关闭时404。数据错误422、版本/幂等/适用条件冲突409、记录不存在404，内部异常不返堆栈。

| 方法 | `/api/experiments` 下路径 | 作用 |
|---|---|---|
| GET | `/context?review_id=...&material_id=...` | 冻结依据、镜头、事实和适用版本 |
| GET/POST | 空路径 | 最近50提案 / 保存提案 |
| GET | `/{id}`、`/{id}/production`、`/{id}/export` | 当前审计状态、制作交接信息、完整JSON |
| POST | `/{id}/select` | 人工选择/拒绝 |
| POST | `/{id}/apply` | selected 后创建一个草稿或新稿件，不派发 |
| POST | `/{id}/attach` | 将确认后准备的同产品新稿草稿接回实验 |
| POST | `/{id}/style-confirm` | 记录本版当前分镜的人工风格确认 |
| POST | `/{id}/await-data` | 审片 ready 后等客户数据 |
| POST | `/{id}/evaluate` | 保存一份两冻结快照描述性评估 |

提案必需 `request_id/review_id/material_id/parent_job_id/hypothesis/target_metric/change_set/comparison_policy/actor`。change_set 为 `{kind:"visual",shot_id,changes}` 或 `{kind:"script",scenes:[{text,fact_ids}]}`；comparison_policy 为 min_reported_days(1–31) 与 min_impressions(0–1e9)。观察指标白名单见能力目录。

后续操作都需 `request_id/expected_revision/actor`；select 另需 decision(selected/rejected)、confirmed=true、note；attach 另需job_id；style-confirm 另需job_id/board_revision/style_id/confirmed=true；evaluate 另需next_review_id/new_material_id。同请求同输入重放原回执，异内容409；查询最新状态用GET，不把旧幂等回执当当前状态。

最多64KiB命令、500事件、100评估/提案；不接任意路径、SQL、模型请求或平台写命令。改画面应用复制失败回滚清理未提交副本；新领域结果和命令回执同事务。输入过期需新建提案，不自动重写旧假设。
