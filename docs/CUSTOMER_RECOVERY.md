# 客户备份、恢复副本与版本升级

日常从“数据与版本”（`/maintenance`）操作。服务仅限本机单用户；不自动投放，不替代事实、文稿、风格、听核或成片审核。

## 先备份

保存编辑，暂停/取消待执行任务，等待识别、对齐、配音和渲染停止。勾选确认后点“创建并校验备份”。维护锁会暂时阻止新的制作修改，完成后自动解除；不要强制退出服务。关闭网页不会取消任务，重新打开可查看记录。

备份保存到当前数据目录旁的 `数据目录名-maintenance/backups/`。每份独立编号，包含 SQLite 一致快照和已登记文件，逐文件SHA256、数据库完整性与引用覆盖均校验。项目、文稿、配音及单句版本、成片、审核、冻结复盘记录都会保留。模型、缓存、日志、未登记文件和API Key不在业务备份中。

点“下载备份 ZIP”，把下载文件复制到其他磁盘；只在同一块盘保存备份不能防范磁盘损坏。ZIP内清单用于完整性校验；备份可能含客户私密资料，请妥善保存。

## 从备份恢复

可点击已完成备份的“恢复为新副本”；另一台机器的备份先在页面选择ZIP，勾选权限确认并导入校验。只接受本产品备份，不接受任意文件夹或压缩包；损坏、缺文件、路径异常和软链接会被拒绝。

恢复结果显示全新目录，点击“打开副本目录”，macOS双击 **启动恢复副本.command**；Windows双击 **启动恢复副本.cmd**。默认8770端口；若被占用，先关闭原8770实例再启动。它会首次准备独立依赖，使用副本内的 `data/`，不会指回原始数据或切换当前页面。打开后先自检，核对项目、原音频、历史成片与审核记录，再继续制作。原目录保留，恢复本身不启动制作、不重新确认审核。

模型需在新安装的首次配置页重新检查/准备。同一系统用户的私有声音文件可继续使用；只在环境变量中配置的Key可能需重新填写，恢复不会读取shell配置或复制凭据。旧成片和旧配音可直接查看，不依赖重新合成。

## 准备新版

1. 向交付方取得新版客户ZIP、发布说明及**另外提供的SHA256**。SHA相同只能证明文件一致，不能证明发行方可信；不要使用来源不明的包。
2. 在页面上传包、填SHA、确认来源。这里只核对外层SHA并登记，未执行代码、未升级。
3. 在对应包卡再次确认，点“先备份，再准备新版”。顺序固定：创建并校验当前数据备份 → 检查发行清单、逐文件SHA、版本与数据schema兼容 → 解压独立新版 → 将备份恢复为新版的数据副本。
4. 任一步失败，旧数据不覆盖，已完成的备份继续列在页面；失败候选不会自动启用。旧安装包缺维护协议或版本降级会拒绝。
5. 准备成功只代表“待启动验收”。打开目录，macOS双击 **启动新版本.command**；Windows双击 **启动新版本.cmd**；服务器不自动执行上传包、不替你安装/激活新版。先自检、核对记录与素材，再用示例项目实际制作一次，逐句听核、完整审片。
6. 满意后在新版继续工作。回退时关闭新版，从旧目录原启动器启动；两份数据不会自动合并，请勿两边同时修改同一项目。

当前版本0.13.1、数据schema14。页面升级支持声明兼容且通过完整校验的发行包；未来跨schema包仍须交付方先完成迁移和旧任务兼容验收，不能仅凭版本号认为兼容。

## 体积、空间与故障

- 备份ZIP导入≤2GiB，发行包上传≤30MiB，业务数据/备份解压≤10GiB，最多20000个ZIP条目；超出请用离线维护工具。
- 上传前检查业务盘和临时盘，上传及复制过程中继续检查，保留至少1GiB余量；解压前按ZIP申报体积再次检查。副本与ZIP需要额外空间。
- 制作中返回“任务/修改未停止”时，不删除数据库或清除租约；回制作页正常暂停/取消并等待停止。
- 服务强制退出会中断维护。页面显示“已中断，未启用”，已完成备份保留；重新发起会生成新目录。失败候选留在维护目录供核对，不自动删除旧版本。
- 校验失败不要跳过文件或改清单。保留原ZIP，用另一个已验证备份重试。
- 目录按钮适配macOS Finder与Windows文件管理器；macOS已实测，Windows仍待真机验收。

原CLI `python -m ecom_video.maintenance backup/verify/restore`继续保留。离线工具操作前停止服务；页面的在线维护锁不代表外部脚本或手动文件操作也受保护。

## 从0.12.0升级的兼容步骤

0.12.0的发行文件白名单固定，不能直接接收带新增Windows文件的0.13.1包；校验拒绝时旧数据和升级前备份会保留，不要改清单绕过。

交付方另附 `ecom-video-upgrade-bridge-0.12.1-20261018.zip` 和独立SHA。先在0.12.0页面对这个**过渡包**执行相同的“上传→先备份→准备→人工启动副本”。进入过渡副本的 `/maintenance`，再登记正常0.13.1包并完成同样步骤。过渡版只更新旧校验器，不在其内制作或配置声音；每一步都保留旧安装和独立数据。普通首次安装直接使用0.13.1，不需要过渡包；0.13.0候选可直接升级0.13.1。
