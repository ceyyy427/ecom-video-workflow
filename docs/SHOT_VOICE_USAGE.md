# 单句配音重做与对齐恢复

入口：[客户商品制作](http://127.0.0.1:8765/create)。先完成事实、文稿、风格、配音听核和分镜。已生成的旧片会保留。

1. 在不满意的镜头下展开“只重做这一句配音”。文字固定取本镜已经确认的原稿，语气和语速沿用当前视频风格（含按商品/气质/人群新推荐的方案）；可换普通音色。
2. 勾选仅发送这一句及计费说明，点“重新合成这一句并对比试听”。每次明确点击只向火山请求这一句，不重新合成其他句，不自动重发云请求。系统在本机对新句做字级对齐，生成独立试听记录；当前成片、分镜、素材和听核不变。
3. 对比“旧句（安全语音区间）”和“新句”。满意后填写采用确认人、勾选说明，点“采用此句，创建待听核新版”。这一步没有新的云请求。
4. 新版保留父片、事实与文稿来源、其他镜头的素材选择、时长和声音片段。新句会重新安排本镜时长和字幕，后续语句绝对时间相应平移。先听核本版字幕、停顿与目标实拍动作，必要时校正时间，再点“确认本版配音听核”。
5. 明确点击“生成成片”。其他镜头可复用已有缓存，最终拼接、音效和混音重新生成。成片停在“待人工审片”，不会自动投放。

新句按30fps帧网格分配1–15秒，保留约150ms前后停顿，成片≤120秒。新句超出目标实拍可用时长或总时长时，采用前阻断并保留原版/试听，不能循环、加速素材来掩盖不足。先调整素材/分镜，再根据页面版本提示继续；修改稿件、声音或节奏边界后旧试听不能直接套用。

安全语音区间由已听核的相邻语句边界确定，可能与视觉帧切点有几毫秒差异。原始24kHz PCM在替换区间之外逐样本保留；新时间线按整样本拼接，其他镜头的局部节奏不变。最终整条响度、背景音乐、音效会重新混合，不声称新MP4的所有音频字节与旧片一致。

## “配音与稿件匹配不足”如何处理

当前曾报错的项目：音频约5.26秒，实际说“倒入杯中，慢慢来；握住瓶身，让水流细一些”，而确认稿是更长的商品说明、技术声明和素材来源，确实不是同稿。重复安装模型或降低匹配门槛不能解决这个原因。

现在的处理：

- 本机识别遇到低匹配，最多再做一次音量预处理与12秒短窗识别，保留两次尝试和较好的证据；Agent所属任务的额外推理先扣预算，仍受取消/期限约束。
- 对有同稿来源回执的TTS，只有识别词是文稿的可信子集（至少3字符、观察词匹配精度≥80%、实际估算语音跨度≤12字符/秒）时，才能形成**明确标记为估算**的时间建议。字级锚点全部标false，原识别内容仍显示，不能自动听核。
- 确实不同稿或无声，不会伪造已匹配的字幕。系统会自动查找有有效事实引用的历史原稿；匹配≥90%时，自动载入第二步的**待确认编辑区**，不改服务器已确认文稿、不批准事实或稿件。核对后手工确认即可继续。
- 如果要保留当前确认稿，点诊断区“保留当前确认稿，改换配音”，再明确合成对应声音或上传正确音频。不会因对齐失败自动反复调用收费配音。
- 单句结果仍异稿/无声时，保留对比试听但禁止采用。模型缺失、音频损坏、资源不足等技术错误仍需按提示处理；不承诺任意不同内容都能自动变成正确字幕。

## 接口与审计

`ShotVersion`：`revision, product_revision, draft_id, job_id, board_revision`，都绑定当前项目和分镜。

- `POST /api/customer-projects/{pid}/voice/shots/{shot_id}/takes`：ShotVersion + `speaker?` + `external_consent:true`。不接收任意文案、提示、速度、地址或Key。
- `GET .../voice/shots/takes/{take_id}/{old|new|raw}`：仅本项目、哈希有效音频。
- `POST .../voice/shots/takes/{take_id}/use`：ShotVersion + `reviewer, confirmed:true`；一次采用、幂等回执；新稿/新声/过时分镜拒绝。

schema v14新增`voice_patches`，记录来源、参数、文件哈希、原/新句、对齐证据及采用后的子版ID。完整拼接声音继续纳入声音历史。每项目最多40条试听/声音/单句记录，素材与保留声音合计≤500MiB；每步校验预算，无自动清理历史。

旧对齐记录按当时适配器、稿件及音频的完整指纹校验后可继续读取，不改写旧听核。当前适配器和父适配器分别记录；换稿/换音频会失效。

验收与回退见 SHOT_VOICE_ACCEPTANCE.md（历史记录或本机文件，未随公开版分发）。
