# 本机交付与故障处理

当前范围：本机单用户、制作与描述性复盘。平台投放由客户完成，人工事实、文稿、风格、听核与审片不跳过。

## 开工前

1. 在项目目录执行 `uv sync --locked`；安装 FFmpeg/ffprobe、中文字体与 Node.js，再在 `render/remotion` 执行 `npm ci`。
2. 运行 `.venv/bin/python -m ecom_video.maintenance check --data var`，或打开“操作指南 → 本机自检与数据保护”点击检查。原 `python -m ecom_video --check` 仍只是旧版基础依赖检查。
3. `ready=true` 仅表示核心依赖存在、已有数据库版本与完整性可读；不证明浏览器启动、模型推理、编码器或云权限已实际验收。磁盘5GiB为提醒线，长片、多版与高清素材应另留余量。
4. 自动选段按 [P8安装说明](P8_USAGE.md) 配置本机 Ollama 并用 `scripts/vision_setup.py` 检查；字级对齐模型安装见 [P5说明](P5_USAGE.md)，安装脚本为 `scripts/setup_p5.py`。这些安装会下载文件，环境检查不会下载或推理。
检查读取的是私有临时副本，不在业务目录创建SQLite旁路文件。检查期间若有并发写入/检查点，可能暂时无法核验；停止业务操作后重试，不把一次未就绪直接当作原库损坏。

5. 配音可上传成品；火山配置按 [授权说明](VOLC_VOICE_AUTHORIZATION.md) 在本机输入。自检只返回配置布尔值，不发送请求、不输出 Key。配置已检测到不等于账户资源已授权。
6. 从启动服务的终端读取环境变量；修改 `~/.zshenv` 后须重新启动服务，已运行的进程不会自动更新。不要把该文件或 Key 放进聊天、商品资料或报表。

本机路径提醒：`--data` 控制业务数据库与素材；FireRed/视觉配置目前固定在**项目** `var/models/`，Ollama权重由Ollama管理，不随 `--data` 自动搬迁。
启动器管理 API、渲染、平台报表和识别消费者；开启 Agent 执行开关时另有 Agent 消费者。日常使用 `scripts/start.sh`，Ctrl-C 停止。平台写入开关 `ECOM_QIANCHUAN_WRITES` 必须不为 `1`；自检会提示是否开启，但不替你修改配置。

## 备份：先停止操作，再创建新目录

暂停/取消待执行及运行任务，等待页面显示停止；停止启动器。如果服务由多个终端分别启动，也要逐一停止。不要强行删除租约绕过检查；计算仍在进行时等待结束。待听核、待审片、草稿与已暂停记录可以保留。

以下目标是示例，父目录先创建，快照目录本身**必须不存在**，并位于数据目录之外：

```sh
mkdir -p "$HOME/Documents/ecom-video-backups"
.venv/bin/python -m ecom_video.maintenance backup --data var \
  --to "$HOME/Documents/ecom-video-backups/customer-20261018"
.venv/bin/python -m ecom_video.maintenance verify \
  --bundle "$HOME/Documents/ecom-video-backups/customer-20261018"
```

备份使用 SQLite backup API，不直接复制运行中的主DB文件；冻结DB后按数据库登记逐项收集原资料、素材、旧成片、字幕/报告、配音历史、单句旧新试听、报表原件及识别证据图。核对数据库完整性、版本、引用覆盖、文件大小与SHA256；任何缺失/改写都失败并清理本次不完整目标，不跳过文件。中途新增编辑可能使备份失败，停止业务操作后重试即可，旧数据不受影响。

不含模型、源码、依赖、渲染缓存、日志、未登记样片/候选目录、Shell环境、系统钥匙串或独立语音配置。`client-projects/` 下授权候选清单不在业务DB内，须另作资料备份。本工具不是整机镜像。
备份含客户商业资料与数据库记录，默认备份根目录700/文件600，**未加密**，只存可信本机/受控存储；不要放入网页静态目录或发给无关人员。SHA256验证完整性，不验证来源真实性，只使用自己创建的可信备份。

## 恢复演练：只恢复到全新目录

```sh
.venv/bin/python -m ecom_video.maintenance restore \
  --bundle "$HOME/Documents/ecom-video-backups/customer-20261018" \
  --to "$HOME/Documents/ecom-video-restored-20261018"
.venv/bin/python -m ecom_video.maintenance check \
  --data "$HOME/Documents/ecom-video-restored-20261018"
```

恢复先重新验证备份，再逐文件复制并复核SHA，拒绝覆盖既有目录和软链接文件，不启动服务、不迁移DB、不自动恢复队列。旧版本DB原样保留；正式启动服务才会按现有 Store 规则迁移，所以须使用匹配程序版本并先保留备份。更高版本DB直接拒绝。
业务快照之外请单独保留源码/锁文件及模型安装依据。迁移路径后钥匙串命名空间会变化，数据库里的授权历史不表示新机器凭据有效；平台与配音凭据只在本机重新配置，必要时由客户重新授权。

确认环境、模型与平台写入关闭后，可显式用另一个端口启动恢复目录的服务核对资料、成片、审批和冻结复盘。完整观看旧片并对比文件指纹；**恢复后不替你批准任何待听核/待审片版本**。演练通过后再决定正式切换数据目录，不覆盖原目录。

## 出错后从哪里继续

| 现象 | 处理与边界 |
|---|---|
| 依赖缺失/数据版本不支持 | 在指南自检，依提示安装或换回匹配程序；不要删除workflow.db重建 |
| 识别未就绪/选段不合适 | 检查本机模型；可明确切人工选段并核对同款/动作，缺镜头补拍，不用不相关图凑片 |
| 配音资源未授权 | 检查同项目语音服务和Key，重启读取新环境；不要重复盲目合成，已获音频优先复用 |
| 配音与文稿不匹配 | 对照识别内容/历史原稿，换回对应稿件或配音；人工确认后重新对齐，不伪造匹配或自动听核 |
| 渲染失败/磁盘不足 | 记录任务ID和结构化错误；释放空间、核对素材/依赖后按页面重试，保留旧片，不删除原素材或数据库 |
| 备份被阻止 | 先处理排队/运行任务或活动租约；缺失/改写素材需定位并修复原件后重试，不绕过校验 |
| 中断/结果未知 | 重开原项目/运行记录核对已完成回执，再按页面恢复；未知平台结果先由客户核对，不重试平台写入 |
| 报表不可比较 | 检查账户、素材绑定、等长日期和币种/时区/归因窗口；未知和缺失不补零，不强判效果 |
